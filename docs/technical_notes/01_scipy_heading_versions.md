# 技術ノート 01: SciPy のバージョンによる heading 計算の差

> 後輩が同じ問題に遭遇したときの参考用。**現象・原因の切り分け方・対処**を整理する。
> 一次ログ（数値比較の詳細）は研究室Mac上にあり、本文書更新環境では再照合していない。ここでは報告された事実と、
> 追試時に確認すべき点を書く。推測の数値は書かない。

## 現象

FP-Nav / Habitat 系の方位（heading, エージェントの向き）計算が、**SciPy のバージョンによって異なる結果**を返すケースがある。
本研究では **SciPy 1.10.1 と 1.13.1** を比較し、差異が出る条件を確認した（報告）。

## なぜ起きるか（切り分けの観点）

- heading は通常、エージェントのクォータニオン姿勢（Habitat の `agent_state.rotation` など）を
  `scipy.spatial.transform.Rotation` で回転へ変換し、オイラー角や前方ベクトルを得て算出する。
- `Rotation` のオイラー角変換（`as_euler`）は、**ジンバルロック近傍の規約・分岐や数値実装がバージョン間で変わり得る**。
  同じ入力でも、境界的な姿勢では返る角度が版によって変わることがある。
- そのため「どの SciPy で算出したか」を固定しないと、同じシーン・同じ pose でも地図に描く方位矢印がずれ得る。

> 注: 具体的にどの関数・どの姿勢で差が出たかの厳密な数値は一次ログ側にある。上記は一般的な原因の整理であり、
> 追試時は実際に 1.10.1 と 1.13.1 で同一 pose を変換して差分を確認すること。

## 本研究での対処

1. **主条件の SciPy を 1.10.1 に固定**した（報告）。環境を再構築するときはこの版を明示する。
2. **幾何的な地上真値と照合**した: エージェントの**カメラ前方ベクトル**を独立に計算し、地図上に描かれる矢印方向と一致するかを確認。
   オイラー角の版依存に頼らず、前方ベクトルという曖昧さの少ない量で裏取りする、という方針。
3. **公式 FloorplanNavigator で描画**し、**8エピソード**の向きを目視・数値で検証（報告）。

## 後輩への教訓

- heading を含む再現では **SciPy のバージョンを必ず固定・記録**する（`pip freeze` を実験記録に残す）。
- `Rotation.as_euler` の戻り値を「版に依らず同じ」と仮定しない。**前方ベクトルなど規約依存の小さい量で照合**する。
- 方位がずれると地図上の矢印・軌跡の向きが狂い、モデル入力（右半分の地図画像）が変わるため、**判断の再現性に直結**する。
