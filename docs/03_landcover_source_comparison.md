# 既存分類済みデータ vs LiDAR独自分類
## 精度・網羅性・作業量の比較と、マッチング目的に照らした再設計

**作成日:** 2026-10-11
**問い:** 多摩地域の都市公園内部について、Forest / Grass / Water に相当する分類済みデータは本当に存在しないのか。既存データのクリップと LiDAR 独自分類を比較せよ。
**前提:** 本研究の目的は植生分類アルゴリズムの開発ではなく、**内部自然環境が類似する公園を妥当に選定すること**である。

---

# 0. 結論（先に）

**ご指摘は正当でした。既存の分類済みデータは「存在しない」のではなく、存在します。**東京都「土地利用現況調査」には森林・原野・水面のクラスがあり、公園内部を細分し、多摩全域をほぼ完全に被覆します。私はこれを「土地利用であって土地被覆ではない」と前回切り捨てましたが、**実データを開いて確認していませんでした。**

ただし実際にクリップして測った結果、**マッチング変数としては使えない**ことが分かりました。理由は精度ではなく**識別力の欠如と、誤差が公園面積と相関すること**です（§2）。

一方で、ご指摘のおかげで**独自分類の作業量を大幅に削減する経路**が見つかりました。既存の公式データで置き換えられる部分が想定よりずっと多く、**LiDAR から自前で作る必要があるのは DSM だけ**になります（§4）。結果として、最大の未解決リスクであった植生判定閾値（F8）も不要になる見込みです。

東京都オープンデータカタログの CKAN API に「緑被」「植生」「樹林」「土地利用現況」「みどり率」「緑地」「水面」で検索し、該当データを実際に取得して中身を確認しました。

| データ | 内容 | 多摩の公園内部に使えるか |
|---|---|---|
| **緑のオープンデータ 樹林地** | 全14レイヤ中の1つ | **不可（§1.1）** |
| **緑のオープンデータ 水系** | 河川・運河／上水・用水／湖沼／干潟／湧水 | 補助的に可 |
| **土地利用現況調査 R4 多摩** | 495,407ポリゴン、27分類 | **要検討 → §2** |
| H21緑被分布／樹林分布 | 品川区のみ、平成21年(2009) | 不可（区部、かつ古い） |

| 環境省 自然環境保全基礎調査 植生図 | 1/25,000 | 不可（最小図示面積が過大） |
| 国土数値情報 土地利用細分メッシュ | 100 m | 不可（1画素=1 ha） |
| JAXA HRLULC / ESA WorldCover | 10 m | 不可（Control中央値931 m²に対し混合画素が支配） |

## 1.1 緑のオープンデータ — 仕様書で確定した2つの事実

データベース定義書・ファイル一覧の原文を取得しました。

**(1) 樹林地は公園を明示的に除外している**

> 樹林地：**300㎡以上の一団の樹林地 ・公園緑地等の開園区域と重なるものは対象外です**
> （「緑のオープンデータ ファイル一覧」および「データベース定義書」）

研究者が以前のGIS調査で発見していた仕様が、**一次資料で確定**しました。推測ではありません。最小単位が300 m²である点も、Control中央値931 m²の公園には粗すぎます。

**(2) 草地レイヤは存在しない**

全14レイヤは `公園・緑地等 / 街路樹 / 樹林地 / 農地 / 崖線 / 丘陵地 / 山地 / 水系 / 民間開発等による緑 / 公共施設の緑 / 自然公園 / 都市計画法・都市緑地法等 / 条例等 / 公的賃貸住宅の緑` であり、**草地・芝地に相当するレイヤは1つもありません。**Grass% はこのデータセットからは原理的に算出できません。

**(3) 副産物：面積属性と幾何面積の乖離は公式に説明されている**

> GIS データの属性情報に面積情報が記載されている場合は、ポリゴンの面積と乖離がありますのでご注意ください（属性情報の面積数値は公表されている調書や所管提供資料等に基づく数値です）
> （「利用に当たっての注意事項」）

私が検出した属性面積と幾何面積の不一致（Treatment 3/30、Control 198/8,193）は、**データ提供者が想定済みの既知の性質**でした。Protection Ratio の分母に幾何面積を採る判断（J3）の根拠がこれで補強されます。

# 2. 土地利用現況調査を実際にクリップして測った

**これが本命の候補でした。**495,407ポリゴン、EPSG:6677、分類コードに `900 森林` `800 原野` `620 採草放牧地` `700 水面・河川・水路` を持ちます。Forest / Grass / Water に対応しうる構造です。

## 2.1 公園内部は確かに細分されている

Treatment 30公園にクリップした結果、**全30公園で被覆率100%**、かつ内部は複数クラスに分かれていました。

| 公園名 | 公園・運動場等 | 森林 | 原野 | 水面 |
|---|---:|---:|---:|---:|
| 城山手緑地 | 2.0% | 97.5% | 0.0% | 0.2% |
| 滝山台緑地 | 0.2% | 61.3% | 36.0% | 0.0% |
| 多摩平第６公園 | 56.3% | 43.2% | 0.0% | 0.0% |
| 清瀬せせらぎ公園 | 7.2% | 2.0% | 2.6% | 60.8% |
| 前沢第３緑地 | 100.0% | 0.0% | 0.0% | 0.0% |

「土地利用であって公園内部は単一区分」という私の前回の記述は**誤りでした。**

## 2.2 しかしControl 3,767件に広げると破綻する

多摩地域の Control V2 全 3,767 公園にクリップしました。

| 指標 | 値 |
|---|---:|
| 被覆率95%未満の公園 | 9 / 3,767（被覆は実質完全） |
| 公園・運動場等が95%以上を占める公園 | 1,370（**36.4%**） |
| 森林% = 0 の公園 | 3,249（**86.2%**） |
| **森林%・原野%・水面% がすべて 0 の公園** | **2,978（79.1%）** |

**マッチング変数3つがすべてゼロになる公園が8割**です。ゼロの変数では公園を識別できません。

## 2.3 ゼロは真のゼロではない — 面積に依存する人工的なゼロ

| 公園面積 | n | 3変数すべて0の割合 | 森林%の中央値 |
|---|---:|---:|---:|
| < 300 m² | 844 | **92.4%** | 0.0 |
| 300–1,000 m² | 1,160 | **87.0%** | 0.0 |
| 1,000–3,000 m² | 963 | 81.9% | 0.0 |
| 3,000–10,000 m² | 474 | 58.9% | 0.0 |
| > 10,000 m² | 326 | 37.1% | 0.0 |

**ゼロ率が公園面積に強く依存します。**これは単なるノイズではなく、**公園面積（それ自体がマッチング変数）と相関する系統的な誤差**です。面積でマッチングしたうえで、誤差が面積に依存する変数を重ねると、マッチングはかえって歪みます。

## 2.4 LiDAR実測との直接対照 — ゼロが誤りであることの証明

| 公園 | 土地利用現況の森林% | **LiDAR実測の樹冠被覆率** |
|---|---:|---:|
| 多摩平第６公園（Treatment, 4,896 m²） | 43.2% | **86.2%** |
| **山王下公園（Control, 666 m²）** | **0.0%** | **80.5%** |

**山王下公園は、既存データでは Forest 0%、実測では樹冠が8割を覆っています。**

メカニズムも特定しました。多摩平第６公園の土地利用クラスごとに LiDAR 樹冠率を算出すると、

| 土地利用クラス | 面積 | そのうち樹冠 |
|---|---:|---:|
| 森林 | 2,113 m² | 90.9% |
| **公園・運動場等** | **2,759 m²** | **83.0%** |
| 道路 | 24 m² | 48.5% |

> **「公園・運動場等」は低植生のクラスではありません。83%が樹冠に覆われています。**
> 土地利用現況調査は**土地の用途**を記録するもので、用途が「公園」である区画は、たとえ全面が樹林であっても「公園・運動場等」と記録されます。したがって森林%は樹冠量を測っていません。

## 2.5 判定

> **土地利用現況調査を Forest% / Grass% の主データソースとしては採用しない。**
> 理由は精度ではなく、(a) Control の79%で3変数すべてがゼロになり識別力が無い、(b) ゼロ率が公園面積と相関する系統的誤差である、(c) 「公園・運動場等」区画の83%が樹冠であり概念が一致しない、の3点。
>
> **ただし Water については採用する。**§4.2 参照。

# 4. 【再設計】既存データで置き換えられる部分を最大化する

ご指摘の核心は「高精度な分類器を作ることが目的ではない」という点です。これを受けて、**独自分類の範囲を最小化する**設計に組み替えました。

## 4.1 公式DEMの発見 — 自前のDEM補間は不要だった

点群データには LAS（`lp`）とは別に **グリッドデータ `grd25`** が図郭単位で配信されています。実際に取得して中身を確認しました。

| 項目 | 実測値 |
|---|---|
| 形式 | GeoTIFF、1600×1200、0.25 m、EPSG:6677、float32 |
| 内容 | **地表面（DEM）**（地表点Zとの差の中央値 −0.00 m） |
| **欠損率** | **0.00%**（提供者側で補間済み） |
| **ファイルサイズ** | **3.6 MB（zip）／7.7 MB（tif）** — LAS の **1/46** |

自前DEM（最近傍補完）と公式DEMを比較すると、MAE 0.066 m、RMSE 0.269 m。**Forest% への影響は 0.01 ポイント**（86.23% → 86.22%）でした。

> **公式DEMを使う。**自前のDEM補間は結果に影響しないうえ、**その妥当性を論文で弁護する必要がなくなります。**ChatGPT査読の指摘①（DEM補間の精度評価）は、提供者のDEMを使うことで論点ごと解消します。

## 4.2 置き換え後の構成

| 必要なもの | 従来案（独自分類） | **再設計** |
|---|---|---|
| DEM | LAS の地表点から自前で構成＋最近傍補完 | **公式 grd25（3.6 MB/図郭）** |
| DSM | LAS から構成 | LAS から構成（**ここだけは独自が必要**） |
| 建物の除外 | ExG と多重反射率による植生判定 | **土地利用現況調査の建物現況ポリゴン**（R04.zip に同梱済み） |
| Water | LiDAR 無返測域（**未検証**） | **土地利用現況調査 クラス700**（完全被覆） |
| Forest | CHM ≥ 3 m ∧ 植生判定 | **CHM ≥ 3 m（建物を除外）** |

### 植生判定（F8）はほぼ不要だった

公式DEMを使い、植生判定（pen ≥ 0.20 OR ExG > 0.02）を**外した**場合の Forest% への影響を実測しました。

| 公園 | 樹高のみ（CHM≥3m） | 植生判定あり | **差** |
|---|---:|---:|---:|
| 多摩平第６公園 | 86.46% | 86.22% | **0.24 pt** |
| 山王下公園 | 80.30% | 79.96% | **0.35 pt** |

> **最大の未解決リスクであった F8（未較正の分光閾値、Forest の約2割を支配していた）が、0.2〜0.4 ポイントしか効いていません。**
>
> 植生判定が実際に効くのは「背が高いが植生でないもの」＝**建物・構造物**の除外です。それは分光閾値ではなく、**公式の建物現況ポリゴンで直接マスクするほうが確実**です。
>
> → **F8 を廃止し、「CHM ≥ 3 m かつ 建物現況ポリゴン外」を Forest の定義とする**ことを提案します。これにより ExG も RGB も使わなくなり、**RGB の出所・撮影時期の問題（ChatGPT査読②）が丸ごと消滅します。**

### Water は既存データを使う

LiDAR の水面判定は未検証（パイロット2公園に水面なし）であり、検証コストもかかります。一方 Water は**区画スケールの特徴**であり、まさに土地利用データが得意とする対象です。

- Control 3,767件のうち水面を持つのは 3.5%（130件）
- Treatment 30件のうち水面1%以上は 6件（清瀬せせらぎ公園 60.8%、矢川緑地 54.9%、黒川清流公園 12.9% ほか）

水面はごく少数の公園にしかないため、**連続変数ではなく「水面あり／なし」の二値**としてマッチングの制約条件に使うのが適切です。噴水・流れは音源そのものなので、**水面の有無が一致していることはペアの質にとって重要**です。

## 4.3 【PROPOSED】Grass% をマッチング変数から外す

これは研究ノート §14 の FIXED 変数リストの変更にあたるため、根拠を示して判断を仰ぎます。

**根拠：**

1. **Grass% は唯一、未較正の分光閾値を必要とする変数である。**Forest を樹高＋建物マスクで定義すれば分光判定は不要になるが、Grass（低層植生と舗装の区別）だけは分光情報なしには分けられない。
2. **Forest% と情報が重複している可能性が高い。**パイロット2公園では Other%（人工被覆・裸地）がそれぞれ 1.76%、1.44% しかなく、`Grass% ≈ 100 − Forest%` がほぼ成立する。この場合 Grass% は Forest% の裏返しでしかなく、標準化距離に独立な情報を加えない。
3. ただし**2公園だけの観察であり、一般化できない。**

**提案する決め方（データで決める）：**

> 最初の約50公園で Forest% / Grass% / Other% を算出し、
> - Other% の分布（中央値・90%点）
> - Forest% と Grass% の相関係数
>
> を確認する。`Other% の中央値 < 10%` かつ `|相関| > 0.9` であれば、Grass% は冗長と判断してマッチング変数から外し、記述統計としてのみ報告する。そうでなければ残す。
>
> **この判定基準は音響測定前に固定し、Decision Log に記録する。**

外した場合のマッチング変数は、**公園面積・樹冠被覆率・水面の有無** の3つになります。

# 5. 改訂後の作業量

| 工程 | 従来案 | **再設計** |
|---|---|---|

軽減策の候補：
- 公園に重なる図郭のみを厳密に選ぶ（算出済みの `treatment_tile_index_20261011.csv` と同じ方法）
- 1図郭ずつ処理して LAS を破棄し、ディスク占有を抑える
- DSM だけが必要なので、点群から最高点グリッドを作った時点で LAS を消してよい
