## 1.1 研究の論理構造

```
制度上の自然保全指定（東京都条例・緑地保全地域）
        ↓  空間的重複
都市公園のうち Treatment 群
        ↓  内部自然環境特性によるマッチング

「制度上の指定」と「実測音環境」は対応しているか（association）
```

# 2. 土地被覆データに関する未解決の問い（明示化）

Step A に入る前に、「何を決めれば決まるのか」を9点に分解する。以下はすべて**音響アウトカムを見る前に**固定すべき事項である。

| # | 問い | なぜ重要か |
|---|---|---|
| Q1 | Forest/Grass/Water は **land cover（物理的被覆）** か **land use（指定された用途）** か | 音の反射・吸収・散乱に効くのは物理的被覆。用途区分データ（例：土地利用現況調査）は公園内部を単一区分で塗るため使えない |
| Q2 | 「樹林率」は **樹林地（林分としてのまとまり）** か **樹冠被覆率（canopy cover）** か | 研究ノートの用語は「樹林率」。高さベースで算出すると実質 canopy cover になり、概念がずれる（→ §5.4 で論点化） |
| Q3 | 樹林と草地の区別に **高さ情報** を使うか、**分光情報のみ** か | 10m級の衛星分類では都市公園内の芝生と樹冠の分離が困難。高さ（CHM）を使えば原理的に分離できる |
| Q4 | 8,770公園 **全件**に同一処理を適用するか、**段階的（tiered）**に絞るか | 0.25m級処理を8,770件に回すのは卒論スケジュールに対して過大。しかし粗いデータだけでは小公園のmatchingが破綻する |
| Q5 | 観測年次を Treatment shapefile（2025-03-27）と **どこまで揃えるか** | 年次不一致は系統誤差になる。特に Treatment と Control で年次が系統的に異なると致命的 |
| Q6 | 「公園が抽出対象外」というデータ仕様の **実態確認** | 研究者が既に発見済みの最重要リスク。未検証のまま使うと全結果が無効 |
| Q7 | **欠測（missing）と真のゼロ（true zero）** をどう区別するか | Q6 と直結。0% を「植生なし」と読むと誤り |
| Q8 | 分母 A_park の確定（**投影面積・マルチパート・内部リング・重複**） | Protection Ratio と分母を共有するため、ここがぶれると既存の Treatment 30 も揺らぐ |
| Q9 | 公園境界をまたぐ **樹冠のオーバーハング** をどう扱うか | 小公園では境界沿いの街路樹・隣接樹木の張り出しが数%〜十数%に達しうる |

## 3.3 各候補の評価所見

### A. 東京都「緑のオープンデータ」樹林地レイヤ — **主変数には不適。ただし監査用として必須**

研究者の既往調査（修士計画 §27）で、**公園緑地等の開園区域が樹林地レイヤの抽出対象から仕様上除外される**という指摘がある。本研究の分析単位はまさに都市公園であるため、この仕様が事実であれば、

> 樹林地レイヤによる Forest% は、Treatment・Control を問わず **構造的にゼロ付近に潰れる**

ことになり、matching 変数として機能しない。しかも「ゼロ」は植生の不在ではなくデータ仕様に由来するため、**真のゼロと区別できない**（Q7）。

さらに、カタログの注意書きは本データを「概略の位置や区域を表示した参考データ」と位置づけ、境界線の正確性を保証していない。数十〜数百m²オーダーの街区公園に対して面積比を計算する基盤としては、精度保証の面でも弱い。

**判断：Forest% の主データソースとしては採用しない。** ただし、
- 樹林地レイヤの被覆が公園でどう振る舞うかを定量化すること自体が、研究ノートに記載すべき**データ仕様監査の成果**になる
- 修士研究（既存データの再集計可能性と限界）と直結する論点でもある

ため、**監査用レイヤとして保持し、比較対象として使う**ことを推奨する。

> **要確認（最優先）：** `緑のオープンデータ ファイル一覧` および `利用に当たっての注意事項` PDF を入手し、樹林地レイヤの抽出基準・除外規則・原典・調査年次を原文で確認する。この文面が本研究のデータソース選定の根拠記述になる。

### B. 東京都 土地利用現況調査GISデータ — **概念的に不適**

土地「利用」区分であり、公園は内部構成によらず「公園・運動場等」といった単一区分で表現される。Q1 の観点から主変数には使えない。

ただし **Control contamination の補助監査**（例：公園ポリゴンが実は運動場主体であるか等）や、公園種別の外形的確認には使える。

### C. 環境省 自然環境保全基礎調査 植生図（1/25,000） — **解像度不足**

全国を網羅し植生単位で分類されるが、縮尺 1/25,000 の最小図示面積は都市公園のスケールに対して過大である。23区内の多くの公園は「市街地」「緑の多い住宅地」「公園・墓地等」といった人為植生区分に吸収され、内部の樹林／草地分解ができない。

**判断：採用しない。** ただし多摩丘陵部の Treatment 公園（面積が大きい）については、樹林タイプ（常緑／落葉、二次林／植林）の**定性的記述**には有用であり、考察での利用を推奨する。

### D. 国土数値情報 土地利用細分メッシュ（100m） — **不適**

1画素＝1 ha。0.5 ha の公園は1画素に満たない。**採用しない。**

### E. JAXA HRLULC-Japan 10m — **スクリーニング用途としてのみ条件付き採用**

全国10m・15カテゴリ・年次整備あり（2020/2022/2024）、商用利用可、精度検証値も公表されている点で、公的かつ科学的に検証されたデータという要件を満たす。

一方で都市公園への適用には決定的な制約がある。1画素 = 100 m² であり、
- 1,000 m²（0.1 ha）の街区公園 ≒ 10画素
- 画素境界が公園境界と一致しないため、**混合画素が公園全体を支配する**
- 芝生広場と周囲のアスファルト・建物が同一画素に混入し、Grass% が特に不安定になる

**判断：主matching変数には採用しない。** ただし、
- Treatment 公園の多くが多摩丘陵の大規模公園である場合（面積が十分大きければ混合画素の影響は希釈される）
- 8,195件の Control から高解像度処理対象を絞り込む**第一次スクリーニング**

という限定用途であれば有用。採否は §4 の決定ルールに従う。

### F. ESA WorldCover / Google Dynamic World 10m — **不要**

解像度は E と同等で、日本域については HRLULC が精度・情報量で優位とされる。国内公的データを使える状況で海外プロダクトを主データにする積極的理由がない。**採用しない**（感度分析で参照する余地は残す）。

### G. 東京都デジタルツイン 3次元点群 ＋ 0.20m 簡易オルソ — **主データソースとして推奨**

本研究の要件に最も適合する。

**適合する理由**

1. **解像度**：グリッドデータ・微地形表現図とも 0.25m（都の報道発表で確認済）。300 m² の公園でも約4,800セルが得られ、面積比の推定が統計的に安定する。
2. **公園を除外しない**：航空レーザ測量は地表を網羅的に計測するため、「抽出対象から公園を除外する」というレイヤ設計上のバイアス（A の問題）が原理的に生じない。これは本研究にとって決定的な利点であり、**データ仕様の細部に依存しない構造的な理由**である。
3. **高さ情報で Forest / Grass を分離できる**：地表面データ（DSM）が提供されるため、DEM との差分から CHM（Canopy Height Model）を構成し、樹冠（高さ ≥ 閾値）と草地・地被（高さ < 閾値）を物理的に分離できる。10m 級の分光分類では不可能な分離である。
4. **二次利用が可能**：商用・学術・個人利用など用途を問わず二次利用可能と都が明示しており（報道発表で確認済）、論文利用の要件を満たす。具体のライセンス表記は要確認。
5. **座標系**：未確認。都の他のGISデータ（都市計画決定情報GISデータ等）は平面直角座標系第9系であり、既存パイプライン（EPSG:6677）と整合する可能性が高いが、**点群データについては確認していない**。再投影が必要な場合は面積計算を EPSG:6677 側に揃える。

> **上記 1・4 は都の報道発表で確認済、2・3 は提供データ種別から導かれる構造的理由である。5 および点密度・オルソ解像度・図郭区分は未確認であり、製品仕様書の入手後に確定する。**

**既知のリスク（必ず検証・記載すること）**

| リスク | 内容 | 対処 |
|---|---|---|
| **R1 撮影季節（落葉期）** | 航空レーザ測量は地形把握目的で落葉期（冬季）に実施されることが多い。落葉期撮影だと落葉広葉樹の樹冠点が疎になり、**樹冠被覆が過小評価**される。東京の都市公園はケヤキ・サクラ・イチョウ等の落葉樹が多く、影響は小さくない | 図郭ごとの撮影日を取得し記録。Treatment / Control で撮影季節が系統的に異ならないことを確認。異なる場合は pair を同一季節ブロック内に制限 |
| **R2 区部と多摩で観測条件が異なる可能性【未確認】** | 公開日は多摩・島しょ 2023-09-01、区部 2024-10-31 で分かれており（確認済）、都は「令和4年度から2か年計画」で整備と説明している。ここから**測量実施年次が地域で1年程度ずれる可能性**が推定されるが、図郭別の測量実施日・撮影季節は**一次資料で未確認**。実際にずれていれば、Treatment が全件多摩である以上、観測条件が Treatment 変数と交絡する | まず製品仕様書・メタデータで図郭別の測量実施日を確認する。**ずれが実在することを確認してから**、pair を同一データブロック内に組む制約を導入する。確認前にこれを既定事実として扱わない |
| **R3 簡易オルソに近赤外がない** | RGB のみの場合、NDVI が使えず、植生判定を ExG / VARI 等の可視域指数に頼ることになる。建物影・濃緑の人工物の誤分類リスク | 高さ情報を主、分光を従として組み合わせる。影領域は専用フラグを立て、QC対象とする |
| **R4 点群の分類コードの有無** | LAS に地表面／植生などの分類が付与されているか要確認。地盤点が別提供（グラウンドデータ）か、未分類オリジナル点群のみかで処理が変わる | ダウンロード前にファイル仕様を確認。未分類なら PDAL の地形フィルタ（SMRF/CSF）で地盤抽出 |
| **R5 処理コスト** | 1ファイル平均約200MB、1GB超もある。8,770公園全件は非現実的 | §4 の段階的設計で対象を絞る |
| **R6 島しょ部** | 小笠原諸島は対象外 | 本研究が本土部限定であることを明記（「緑のオープンデータ」も本土部のみ） |

### H. 国土地理院 基盤地図情報・空中写真 — **補助**

水涯線は Water% の交差検証に有用。空中写真は Tier 3 の目視判読の代替／補強に使える。

### I. 区市町村の緑被率調査 — **全域適用には不適**

# 4. 推奨するデータセット選定戦略（Step A の結論）

## 4.1 基本方針：単一データセットではなく「主＋監査」の二本立て

| 役割 | データセット | 用途 |
|---|---|---|
| **主データソース** | **G：東京都デジタルツイン 3次元点群 ＋ 0.20m 簡易オルソ** | Forest% / Grass% / Water% の算出 |
| **監査用** | A：緑のオープンデータ 樹林地レイヤ | 公園除外仕様の定量的検証、および「既存主題図では何が見えないか」の記述 |
| **交差検証用** | H：基盤地図情報 水涯線、目視判読 | Water% および最終ペアの精度検証 |
| **条件付きスクリーニング** | E：JAXA HRLULC 10m | 高解像度処理対象が過大な場合のみ |

主データソースを G とする根拠は、**本研究の分析単位（都市公園、多くが1 ha未満）に対して、公園内部を除外せず、かつ樹林と草地を物理的に分離できる唯一の公的データ**であることによる。

## 4.2 処理対象を絞る段階的設計（Tier）

研究ノート §15 の matching 手順は、**第1ステップが「面積caliper内のControl抽出」**である。公園面積は既存パイプラインで算出済みであるから、**Forest/Grass/Water を計算する前に候補を絞れる。**

```
Tier 0  全 8,770 公園
        └─ 分母 A_park の確定（幾何整備・重複解消）※全件
             ↓ 面積caliper（Treatment 30 件それぞれに対して適用）
Tier 2  面積caliper内のControl候補 ＋ Treatment 30
        └─ 点群＋オルソによる高解像度被覆分類 → Forest/Grass/Water
             ↓ 標準化・類似度計算
Tier 3  最終pair候補（想定 20–40 公園）
        └─ 0.20mオルソ上での独立目視判読による精度検証
```

**Tier 1（10m級による全件スクリーニング）は原則として実施しない。**

理由：Treatment が緑地保全地域と重複する公園である以上、比較的大面積の公園に偏ると予想され、面積caliper だけで Control 候補が十分小さくなる可能性が高い。不要な処理を挟むと、工程が増える割に主分析に寄与しない。

**【2026-10-11 更新】決定ルール（実測に基づき確定）**

受領データでの実測（検証報告 §4）の結果、**面積caliper だけでは計算対象が絞れない**ことが判明した。δ = 0.10（面積比 0.79–1.26倍）という厳しい caliper でも、多摩地域内で一意 3,022公園が残る。Control V2 の面積中央値が 0.093 ha と小さく、小規模 Treatment が各々約1,000件の候補を引き当てるためである。

したがって当初案の「N ≤ 600 なら全件」という分岐は成立しない。代わりに **Protection Ratio で Treatment を絞ったうえで、面積近傍 k 件を取る**方式に改める。

> **規則（音響測定前に固定すること）**
>
> Protection Ratio ≥（決定した主分析閾値）の Treatment 各件について、
> **多摩地域の Control V2 のうち |log10(面積) 差| の小さい順に k 件**（同順位は全件）を土地被覆計算対象とする。

実測された作業量（Protection Ratio ≥10% の12件を対象とした場合）：

| k | 一意Control数 | 最大 \|log10面積差\| |
|---:|---:|---:|
| 10 | 114 | 0.045（面積比 1.11倍） |
| 20 | 220 | 0.069 |
| **30** | **320** | **0.090（面積比 1.23倍）** |
| 50 | 512 | 0.146 |

**推奨：k = 30（一意320公園）または k = 50（一意512公園）。**どちらも 0.25m 級処理として現実的であり、面積一致も 1.23倍以内と良好である。最終値は点群処理のパイロット（1公園あたりの実所要時間）を見て決定する。

**Tier 1（JAXA HRLULC 10m による全件スクリーニング）は実施しない。**上記規則で計算対象が十分に絞れるため、10m級の粗い推定値を介在させる必要がない。

**方針上の注意：** 再現性文書 §13 の「固定件数 cutoff を使わない」という既存方針との整合については、検証報告 §4.3 で整理した。要点は、**caliper 内の Control は従来どおり全件 CSV に記録し続ける**（スクリーニングプール）一方で、**土地被覆の計算対象の絞り込みは「matching 基準」ではなく「計算予算の制約」として別建てで宣言する**ことである。

## 4.3 面積caliper の事前固定

Tier 2 の対象集合は面積caliperで決まるため、**caliper 自体も音響アウトカムを見る前に固定する必要がある。**

推奨：公園面積は強い右裾分布を示すため、**対数面積での caliper** を用いる。

```
|log10(A_control) − log10(A_treatment)| ≤ δ,   δ = 0.30 （≒ 面積比 1/2 〜 2 倍）
```

δ = 0.30 は提案であり、データ受領後に Treatment 30 件の面積分布を見て
「各 Treatment に最低 k 件（例 k = 5）の候補が残る最小の δ」
として決める方が防御可能である。この決定も音響測定前に固定・記録する。

# 5. Forest / Grass / Water の操作的定義（Step B）

## 5.1 分母 A_park の定義

```
A_park = 公園ポリゴンの平面投影面積
         [JGD2011 / 平面直角座標系第9系 (EPSG:6677)]
```

- **投影系で計算する**（地理座標のまま面積計算しない）。Protection Ratio と同一の座標系・同一の分母を使うこと。
- park_id 単位で **dissolve** し、マルチパートは1公園として合算する。
- 内部リング（穴）は面積から控除する。
- 都立公園・区市町村立公園・国営公園の3レイヤ間でポリゴンが重複する場合の扱いを明示的に決める（研究ノートには記載がないため **要確認事項**）。重複を放置すると A_park が二重計上され、Protection Ratio にも波及する。

## 5.2 4クラス排他分割

公園内部を、**相互排他かつ網羅的な4クラス**に分割する。

| クラス | 記号 | 定義 |
|---|---|---|
| 樹冠 | F | 植生であり、かつ地表面からの高さ h ≥ h_tree |
| 草地・低茎植生 | G | 植生であり、かつ h < h_tree |
| 水面 | W | 開放水面（池・流れ・修景水面） |
| その他 | O | 人工被覆（舗装・建物・遊具）・裸地・その他 |

```
Forest% = Area(F) / A_park × 100
Grass%  = Area(G) / A_park × 100
Water%  = Area(W) / A_park × 100
Other%  = Area(O) / A_park × 100

Forest% + Grass% + Water% + Other% = 100   （有効観測域において）
```

**Other% は matching 変数ではないが、必ず算出し記録する。**合計が100%にならない場合は欠測の存在を示すため、QC指標として機能する。

## 5.3 判定の優先順位（排他性の担保）

混合・重複を機械的に解消するため、**判定順序を固定**する。

```
1. W 判定（最優先）:  LiDAR無反射域 ∩ オルソ上の水面 → W
2. F 判定:            植生 ∧ (h ≥ h_tree)          → F
3. G 判定:            植生 ∧ (h <  h_tree)          → G
4. 残差:              上記いずれでもない            → O
```

水面を最優先にするのは、水面上の張り出し樹冠を F と W に二重計上しないためである（上から見た被覆としては樹冠が水面を隠すが、本研究では**水面の存在**を音環境の説明要因として扱うため水面を優先する）。この選択は恣意的であり、**研究ノートに明記すべき設計判断**である。

## 5.4 【PROPOSED CHANGE】「樹林率」と「樹冠被覆率」の概念差

研究ノートの用語は「**樹林率**」である。これは通常「樹林地（林分としてまとまった樹木地）が占める割合」を指す。

一方、本メモの Forest% は高さ閾値で定義される「**樹冠被覆率（canopy cover）**」であり、

- 単木の独立樹（公園の孤立木・並木）も Forest に算入される
- 「林分としてのまとまり」は要求しない

という点で**定義が異なる**。

**提案：本研究では Forest% を「樹冠被覆率」として定義し、研究ノートの用語も「樹林率（樹冠被覆率として操作化）」に改める。**

**根拠：**
1. 本研究が見ているのは音環境である。音の吸収・散乱・心理的遮蔽に効くのは林分としてのまとまりではなく、**物理的に存在する樹冠量**である。
2. 都市公園、特に街区公園では「林分」と呼べるまとまりはほとんど存在しない。林分基準にすると Control 側の大半が Forest% = 0 となり、matching 変数として分散を失う。
3. 修士研究の主変数が「樹冠被覆率」であり、概念の連続性が確保される。

**これは研究ノート §14 の FIXED 変数リストに対する用語変更の提案である。採否は研究者の判断を仰ぐ。**（本メモ単独では変更しない。）

なお、まとまりを重視したい場合は、Forest% と併せて
`Forest_patch%`（最小パッチ面積 ≥ 100 m² の樹冠のみ）
を補助指標として算出し、感度分析に使う案もある。

## 5.5 事前に固定すべき閾値（すべて音響測定前に決定）

| パラメータ | 推奨値 | 根拠 / 代替案 |
|---|---|---|
| 樹高閾値 h_tree | **3.0 m** | 都市緑地研究で樹木／低木・草本を分ける際に広く使われる水準。代替 2.0 m で感度分析 |
| 植生判定（分光） | ExG = 2G − R − B の Otsu 閾値、または固定閾値 | 簡易オルソに近赤外がない場合。NIR が含まれるなら NDVI > 0.2 を優先 |
| 解析グリッド | **0.25 m** | 点群グリッドの提供解像度に合わせる |
| 最小マッピング単位 MMU | **1.0 m²**（0.25m グリッドで16セル） | 孤立ノイズ画素を除去。モルフォロジー開closing処理で実装 |
| 有効被覆率の下限 | **coverage_ratio ≥ 0.95** | これ未満の公園は matching 対象から除外（§5.7） |
| 公園最小面積 | **要決定** | 例えば 300 m² 未満は位置誤差が支配的になるため除外する案。研究ノートに記載がないため確認が必要 |
| 樹冠オーバーハング | **公園ポリゴン内に落ちる樹冠のみ算入（クリップ）** | 境界バッファを設けない。代替案は ±2 m バッファでの感度分析 |

## 5.6 欠測の類型化（Step B の要求事項）

> **原則：欠測を「植生なし」と解釈しない。** 欠測は 0% ではなく NA として扱う。

| 型 | 内容 | 検出方法 | 扱い |
|---|---|---|---|
| **M1** データ範囲外 | 点群の整備対象外図郭（島しょ部等） | 公園ポリゴン ∩ 点群図郭インデックス | 解析対象外。該当公園数を報告 |
| **M2** 仕様上の除外 | 主題図側で公園が抽出対象外 | 樹林地レイヤの公園内被覆率を全公園で集計し、分布が 0 に潰れていれば仕様除外の証拠 | **緑のオープンデータを主データソースにしない根拠として記述**。値は NA 扱い |
| **M3** 観測欠落 | 点群の無反射・低密度域、オルソの雲・影 | 点密度マップ（点/m²）、影マスク | coverage_ratio に反映。水面由来の無反射は M3 ではなく W と判定 |
| **M4** 標本不足 | 公園が小さく有効セル数が不足 | 有効セル数 < 1,600（= 100 m²相当） | flag を立てて matching 対象から除外 |

各公園に以下を付与する：

```
coverage_ratio = (有効判定面積) / A_park
n_cells_valid  = 有効セル数
flag_missing   = {OK, M1, M2, M3, M4}
data_block     = {区部, 多摩}        ← R2 対策
survey_date    = 図郭ごとの撮影日     ← R1 対策
leaf_season    = {落葉期, 着葉期, 不明}
```

**`coverage_ratio < 0.95` の公園は Forest/Grass/Water を NA とし、matching 母集団から除外する。除外件数は論文に報告する。**

### 工程 3 — 対象公園の絞り込み

1. Treatment 30 件の面積分布を出力
2. 対数面積 caliper δ を §4.3 の規則で決定・固定
3. Control 候補を抽出し、N を確定
4. §4.2 の決定ルールで Tier 1 の要否を判定

成果物：`tier2_targets.csv`（park_id, role, matched_to_treatment_id, A_park, data_block）

### 工程 4 — 高解像度被覆分類（Tier 2）

公園ごとに以下を実行する。

```
4-1  公園ポリゴンに 5 m バッファ → 必要図郭を特定 → 点群/オルソ取得
4-2  点群から DEM（地盤点）と DSM（最高点）を 0.25 m グリッドで生成
     ※LAS に分類コードがなければ PDAL の地形フィルタで地盤抽出
4-3  CHM = DSM − DEM。負値は 0 にクリップ
4-4  オルソを 0.25 m にリサンプリングし、植生指数（NIR があれば NDVI、
     なければ ExG）を計算
4-5  水面マスク: 点密度 ≈ 0 の連結領域 ∩ 植生指数が低い領域
     → 基盤地図情報 水涯線で交差検証
4-6  §5.3 の優先順位で F / G / W / O を判定
4-7  MMU 1.0 m² 未満の孤立領域を除去（opening → closing）
4-8  公園ポリゴンでクリップし、クラス別面積を集計
4-9  coverage_ratio, n_cells_valid, flag_missing を算出
```

成果物：`landcover_tier2.csv`（park_id ごとに forest_pct, grass_pct, water_pct, other_pct, coverage_ratio, n_cells_valid, flag_missing, h_tree, survey_date, data_block）

### 工程 5 — 欠測評価と分類誤差の点検

1. `flag_missing` の分布を Treatment / Control 別に集計
2. **緑のオープンデータ樹林地レイヤによる Forest% を同じ公園群で算出し、点群由来 Forest% と散布図比較**
   → 樹林地レイヤ側が系統的にゼロへ潰れるなら、公園除外仕様の**定量的証拠**となり、論文のデータ仕様監査節に使える
3. 撮影季節（`leaf_season`）別に Forest% の分布を比較し、落葉期バイアス（R1）の大きさを推定
4. `data_block`（区部／多摩）別に Forest% 分布を比較（R2）

**QC-2：** Treatment と Control で `data_block` / `leaf_season` の分布が偏っていないか検定。偏っている場合は **pair をブロック内に制限する制約を追加**し、その判断を記録する。

### 工程 6 — matching 変数の標準化

1. Tier 2 対象のみで記述統計（n, mean, SD, 中央値, 四分位, 最小, 最大）を出力
2. `log10(A_park)`, `forest_pct`, `grass_pct`, `water_pct` を z 標準化
   - **標準化は Tier 2 集合（Treatment + 候補Control）内で行い、母集団全体では行わない**。この選択を記録する
3. `water_pct` はゼロ過剰分布になる可能性が高い（池のある公園は少数）。このまま z 標準化すると距離計算を歪めるため、
   - 案(a) `water_pct` を二値化（水面あり／なし）して exact match 条件にする
   - 案(b) そのまま連続変数として重みを下げる
   いずれかを**事前に固定**する

成果物：`matching_variables.csv`

### 工程 7 — 品質検査と限界の文書化

1. **Tier 3 検証：** 最終 pair 候補（20–40公園）について、0.20m オルソ上で独立に層化ランダム点（例 1公園あたり100点）を判読し、自動分類との**混同行列・全体精度・クラス別 Producer's / User's Accuracy・Kappa** を算出して報告する
2. 感度分析：h_tree = 2.0 m で全工程を再計算し、matching 結果の安定性を確認
3. 限界の明記：
   - 樹冠被覆率であり林分としての樹林率ではないこと（§5.4）
   - 落葉期撮影による落葉樹過小評価の可能性（R1）
   - 区部／多摩の観測年次差（R2）
   - 公園ポリゴン自体が「概略の区域を示す参考データ」であること（分母の不確実性）
   - 近赤外欠如による植生判定の制約（R3、該当する場合）

成果物：`accuracy_assessment.csv`, `limitations.md`

## 7.1 【方法論上の指摘】樹林率でマッチングすることの意味

研究ノートは「内部自然環境特性が類似する公園同士を比較する」と明示しており、樹林率でのマッチングはその設計意図に沿っている。ただし、推定対象（estimand）が何になるかは論文で明示すべきである。

> 緑地保全地域の指定は、一般に**樹林が多い土地に対して行われる**。したがって樹林率をマッチング変数に含めると、
> 「保全指定 → 樹林が多い → 音環境が静か」
> という**植生を経由する経路を意図的に遮断**することになる。

結果として本研究が検証するのは、

> **内部植生構造を揃えたうえでなお残る、保全指定と音環境の対応**

であり、保全指定の総合的な対応関係ではない。これは設計上の誤りではなく**意図された限定**であるが、

- 差が小さく出た場合に「指定に意味がない」と読まれないよう、考察で明示的に説明する必要がある
- 補助分析として、**樹林率でマッチングしない（面積のみでマッチングする）版**を併記すると、どれだけが植生経由かを示せる

ことを提案する。これは研究ノートの FIXED 事項に抵触しない追加分析である。

## 7.2 【方法論上の指摘】分母の不確実性

Protection Ratio と Forest/Grass/Water は **A_park という同一の分母**を共有する。東京都オープンデータのカタログは公園ポリゴンを「概略の位置や区域を表示した参考データ」と位置づけており、境界精度は保証されていない。

小公園では境界誤差が面積比に直接効くため、
- 公園最小面積の下限設定（§5.5）
- 最終ペア候補については、0.20m オルソ上で**境界の妥当性を目視確認**する

ことを推奨する。最終ペアは10組前後であり、目視確認のコストは小さい。
