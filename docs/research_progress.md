## 2. 実施した内容と結果（本人報告）

### 段階0: 適格性調査（本リポジトリで検証可能）

- FP-Nav が「地図入力を条件に行動テキストを出す学習型VLM（Qwen2.5-VL-7B微調整）」であることを、公式コードの
  `file:line` を辿って確認（[`reproduction/FP_NAV_FEASIBILITY_REPORT.md`](reproduction/FP_NAV_FEASIBILITY_REPORT.md)）。
- 地図は入力画像の右半分に固定描画され、RGB・指示を固定して地図だけ差し替え可能であること、
  `predict_inference` が Habitat 非依存で1判断を単体実行できることを確認。
- この段階は**実コードの読解に基づく**ため、本リポジトリ上で追試・検証できる。モデルのロードや推論は**この段階では未実施**。

### 段階1: シミュレータ検証（Habitat-Sim 0.3.3）

- Matterport3D 形式シーンを Habitat-Sim で読み込み、RGB観測と移動行動の動作を確認（報告）。
- **R2R の ep85・ep280 で GT 行動を再生**し、正解経路の終点への一致、開始位置→ゴールの測地距離が記録値と一致、を確認（報告）。
- 関連する取り違えの検証記録: [`technical_notes/02_episode_id_vs_trajectory_id.md`](technical_notes/02_episode_id_vs_trajectory_id.md)。

### 段階2: 方位・地図描画の検証

- 公式の heading 計算が **SciPy のバージョンによって異なる結果**を返すケースを確認。SciPy **1.10.1 と 1.13.1** を比較し、
  主条件を **1.10.1** に固定（報告）。
- カメラ前方ベクトルと地図上の矢印方向を照合。公式 FloorplanNavigator で画像を描画し、**8エピソード**の向きを検証（報告）。
- 検証記録: [`technical_notes/01_scipy_heading_versions.md`](technical_notes/01_scipy_heading_versions.md)。

### 段階3: モデル入力の再現性確認

- RGB画像とフロアプランを横連結して入力を生成し、過去のPilotと画像・テンソルを比較（報告）。
- **RGB画像の画素差は、開始位置の小数第3位への丸め**に起因することを確認（報告）。
- **ハッシュ不一致は、int32 へのキャストと SHA-256 の短縮表示という計算方式の違い**であることを確認（報告）。
- 検証記録: [`technical_notes/03_rgb_coordinate_rounding.md`](technical_notes/03_rgb_coordinate_rounding.md)。

### 段階4: 閉ループPilot（R2R val-seen ep85）

報告された内容:

- モデル判断: **5回**／基本移動動作: **12回**（回転6・前進6）／解析失敗: **0回**
- モデル出力: 左30°回転を**3判断**、その後75cm前進を**2判断**
- 行動実行後の観測更新と次の判断が動作することを確認

**限界（明示）**:
- これは**モデル判断5回の上限で打ち切ったPilot**である。
- **完走時の SR・SPL などの性能評価結果ではない。**
- **原著の成功率を再現できたという主張ではない。**
- Pilot が示すのは「地図付き入力でモデルが行動を判断し、観測更新→次判断のループが回る」という動作確認までである。

### 段階5: 完全閉ループ評価（本実行）

- R2R の ep85・ep280 を対象とした本実行を**計画・承認済み**。
- **本更新時点で、その実行結果は確認できていない（未確認）。**
- 実際の結果ファイルを照合できた場合に限り、SR/SPL 等をここに追記する。それまでは数値を書かない。

## 3. 限界・リスク

1. **一次ログ未照合**: 段階1〜4は本人報告であり、本ドキュメント更新環境では実ログを再照合していない。
   研究室Macのログ・成果物をリポジトリに取り込み、第三者が追試できる形にすることが必要。
2. **測位はオラクル**: 地図上の自己位置は Habitat の ground-truth pose 由来。研究で操作できるのは地図の「表示・内容」であり「測位誤差」ではない。
3. **学習時の地図ノイズ拡張**: モデルは地図破損に設計上ある程度頑健化されている。地図関連の実験結果はこの頑健化と切り分けて解釈する必要がある。
4. **mac 向け改変の数値影響**: flash-attn→sdpa/eager、device、dtype の変更は「同じモデルの実装・精度差」。greedy なら出力はほぼ不変の見込みだが、**要検証**（詳細は [`reproduction/FP_NAV_INFERENCE_SPEC.md`](reproduction/FP_NAV_INFERENCE_SPEC.md) §6）。
5. **Habitat フル評価の環境制約**: 著者評価系（Habitat-sim/lab v0.1.7, CUDA）は Apple Silicon 非対応。大規模な成功率再現は学内/研究室の Linux+NVIDIA 機が必要。
